# 验证:「修好了」要拿什么证明

CLAUDE.md 的 Verification Rule 是结论;这里是它背后的具体失败形状和操作细则。

## 同判据前后数字

- 任何「修好了」都附**同一判据下的前后数字**(如「同秒 HP 矛盾 26/50 → 0/50」)。给不出就明说给不出。
- 2026-07-20 的两次自验证失败都不是复读代码发现的:
  - 按「统一 HP 采样半径」修,根因写得头头是道,实测 **26/50 → 26/50 一个数没动**。真根因是查询时刻不在同一渲染网格——先取最近样本再用半径决定接受与否,改半径只能把值变成 null,永远不改数值。
  - 只查了一个样本就外推整类(「只是记号歧义」),被一个反例推翻:同一技能私有表 45 s vs 主路径 65 s,是重复常量漂移。**别只查一个样本就外推整类。**
- 涉及「两处对同一事实不一致」时,先问**是不是在断言同一件事、查的是不是同一时刻**,再问容差 / 半径。

## 判据要做成门,不做一次性脚本

- 优先把判据写成确定性文本检查,进 `packages/eval/src/quality/promptQualityCheck.ts` 的 `hardFailures`。一次性脚本随会话消失:CJK 泄漏「0/1245」当年只是脚本,两个月后回归到 230/309,直到做成 `checkCjkLeak` 才守住。
- **行为零变化唯一算数的证明**:改前改后对同一批真实对局产出完整 findings prompt 的 SHA256 + 字节数,**并且**逐类候选计数(`packages/eval/scripts/acceptanceCapture.ts`)。`acceptanceHash` 只覆盖 findings prompt,上下文行要另外数。

## 机制成立 ≠ 因果归属成立

两件事分开验。2026-08-03 一轮里好几个候选机制在 HEAD 上确实存在且能确定性复现,但 `git diff <上个 release>..HEAD -- <文件>` = 0 行,`git log -S` 证明它们比用户说的起点早 2–3 周,解释不了「现在才有」。验因果三板斧:

1. 引入时间(blame / pickaxe);
2. 与嫌疑改动的**具体耦合点**(共享状态 / IPC channel / 子进程 / 布局盒子,说不出就存疑);
3. 磁盘或日志上**应该留下的痕迹**。

commit message 里把「我修的真 bug」和「用户报的症状的根因」分开说。

## 检查器自己先验证

- 全量审计里两次最大的假警报都来自自己的检查器(按窗口起点盖戳 → 4,075 条假违规;过时格式 → 1,538 条假丢弃)。信违规之前先在手核样例上验映射,再做变异测试。
- **任何扫描先看扫了多少**:一个 invariant 扫描在 `.gz` 归档上扫了 0 场还报「零违规」。
- **探针测的层必须是出问题的层**:吸收语义探针曾只量没有消费者的 L3 层,修没修都看不出来;它的真值本身也错过(按整场快照而不是按回合)。
- 「正确性探针自己也要被验证」:一次「35.6% 冤枉」的结论,一半是把 GCD 连点的拒绝误读成冷却,结论反转。
- 声称「这条测试守住了 X」,就手动把 X 改坏跑一遍。自动更新那轮十轮复核里五处假守卫全靠手动改坏实现才发现。
- **pin 错值的测试比没有测试更坏**(OBS 两个配置 bug 曾被旧单测一起钉住);夹具同时放「被测分支的事件」和「兜底路径的事件」会让测试不可能失败。

## 审查 / 子代理的「bug 报告」要自己复核

挖掘代理、外部审查、第二个 AI 报的 bug 都要自己探针复核(一次「BROKEN 事件时长虚增」被语料 1,428/1,428 否证)。审查建议的修法也要先拿真实对局量再收:「必须有 IMMUNE 才算」会误删 115 条,「本人位置缺失就弃权」会冤枉人。
