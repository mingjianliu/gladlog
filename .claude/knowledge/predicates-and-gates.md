# 谓词与门:Shared-Predicate Rule 之外的教训

CLAUDE.md 的 Shared-Predicate Rule 与 `docs/predicate-index.md` 是规则本体。这里只留它们没写的形状。

## 渲染网格与采样

- HP 采样必须先 floor 到渲染秒(`utils/renderGrid.ts`),再做任何门规会重算的检查。按压行打印的 HP 是按压瞬间的读数(`hpAtPress`),这是 CLAUDE.md 里写明的签字例外,别把它改回网格,也别把别的读数挪离网格。
- **刻意的例外(勿翻案)**:CC / 敌方爆发这类「按压瞬间」判定用 raw t。CC 42.2 s 开始、饰品 42.4 s 按,按 42 s 查会误判「无 CC」。曾有人提议「全部 floor」,已驳回。
- LoS 要用**同时刻**的位置样本;插值或非同时样本会造出幽灵 LoS。从小数时刻扫描与门规重读整秒是两个不同的瞬间。

## 谓词索引的局限

- 存在性断言只抓改名,不抓值漂移;值层面靠 producer ⇄ gate 的逆向测试。**不要加「断言常量等于自己字面量」的值锁测试。**
- 能做成结构性共享(import / 推导)的,优先于检测漂移。
- 共享谓词保证一致,但**共享的数据烂了两边一起烂**:覆盖门和 coverage manifest 共用同一白名单,白名单收错 id 时两边同时失明,门规永远抓不到(见 [whitelist-rot.md](whitelist-rot.md))。

## 指控集 vs 回应集

收紧「X 就绪却没按」的 ready 集合,**不能顺手缩小「有没有回应」的 spent 集合**。2026-09-23(GH #103,`REACTION_WINDOW_S = 1`,用户裁「1 秒内转好的不要管」):把 cd-hoarded 的 ready 换成严格的 `cdReadyInTimeAt`,同一个集合也被用作 spent 检查,于是「危机前 0.4 s 转好且确实按了」不再算回应,另一面没按的墙变成**新的**指控。修法 = 两个集合:指控用严格版,回应用状态版(`cdAvailableAt`)。

- 信号:一个更严格的门让计数**上升**,就是这种错。聚合 delta(+1)掩盖了 9 增 8 减。
- 做法:收紧任何「有 X 没按」谓词时,按 owner diff 候选 id,要求新增 = 0(除了上限替换)。

## 候选门会被富上下文绕过

候选门工作正常,但另一段上下文(装备表、统计表、时间轴标注)无条件暴露同一事实,模型照样说出被门挡住的话。2026-08-01:承压门挡住了 cd-waste,但 `<player_loadout>` 无条件给未用减伤打 `[UNUSED]`,模型照样「你没用减伤」。修法 = 与门同一常量的守护注。新增 / 审查任何候选门时,grep 富上下文里同一事实的裸暴露面:要么同谓词加守护注,要么门内联渲染。不删事实,只声明教学立场。

## 门装在候选层,不只渲染层

missed-cleanse 窗口按队伍口径算,facts 不带「谁能驱」,模型就对不能驱散的 owner 写「你该驱这个诅咒」。修 = 候选门 `canDefensiveCleanse` + facts 带可驱散者:37/200 → 0。散文里的技能名没有职业归属校验,守护注是唯一防线。

## 可行性门与三态铁律

- 责难类候选上线前固定审查**可行性**:当时做得到吗(资源就绪、可反应、够得着)。驱散家族(`missedPurgeEvents`)三样都查,照抄。
- **三态铁律**:`losReachable` 等返回 true / false / null;**无位置数据必须 null,不改判**。「无数据当不可行」会吞掉全部非 advanced 语料。
- 免疫覆盖(`immunityCoversSpell`)同理:缺数据 = 未知,不是「挡不住」。种族技能更极端:日志没有种族字段,种族谓词**永远不得给出 "no"**。

## 「窗口内任何时刻」陷阱

「窗口内任何时刻满足 X 就豁免」会把长窗口整段豁免(34 秒的诅咒中间只被心控 3 秒)→ 按覆盖时长和已有阈值判。

## 事实行的证据是光环行

「CC / 效果落地 N 秒」的验证证据必须是**光环行**,永远不是施法行。第一版门规退回施法行,放过了编造的 99 s。

## 合并到「标准谓词」前先量

标准谓词本身也可能是错的。死代码审计里「合并会改输出」的那一档,每条都单独提交、单独给前后数字。
