# 代码注释与字符串的语言边界

全仓 TS/TSX 代码注释中文 → 英文已在 2026-08-02 完成(约 7,200 行 → 134 行)。剩下的 134 行**全部应保留,别再「顺手清干净」**:

- 中文检查器本体:`causalLint.ts` / `causalLint.test.ts` / `spellNameZhLint*`——注释写的就是它们要匹配的中文模式与语料样本,译掉等于把规格从代码里删掉。
- 英文注释里引用的中文数据样例(本地化单位名、DR 标签、类别别名、「衰减 N%」读数等)——译掉注释就与代码 / 断言对不上。

## 写新代码时的边界

- `.ts / .tsx` 的**注释**写英文。
- `it(...)` / `describe(...)` 的**用例名保持中文**;UI 文案、错误文案是产品字符串不是注释。
- eval 脚本里 console 输出的中文统计文案是 CLI 输出字符串,不在范围内。
- `styles.css` 整个文件从来不在范围内,至今全中文——在里面写中文注释是对的。
- 新写注释前先看同文件邻居是什么语言;动手前 `git fetch` 看一眼目标文件在 origin/main 上的注释语言。
- 文档语言规则见 CLAUDE.md 的 Bilingual Docs Rule 与 `docs/developer-guide.md` 的语言策略节。

## 批量改注释的三个坑

1. **散文行不能以指令名开头**:译文换行后一行正好以 `// @ts-expect-error` 开头 → TS 当成真指令 → TS2578 编译红。
2. **生成物必须成对改**:生成器模板里的头注释是字符串字面量,它产出的是生成文件的注释。只改一边 → 下次重跑数据写回原文或混排。
3. **脚本里的裸反引号**:规则文本用反引号模板串写、内部又含反引号片段 → 提前截断,整个变量求值成 `NaN`,下游代理拿到空指令。派活前先求值一次确认是正常字符串。

复核法:逐文件比对**中文字符串字面量**改前改后是否一致(抓越界改字符串);先按状态机剥掉注释再扫字符串,比内容不比引号(prettier 会规范引号)。
