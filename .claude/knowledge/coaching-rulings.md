# 教练口径的用户裁决

这些都是「指控集怎么划」的价值判断:代码和提交能看到结果,看不到是谁定的、为什么。有人想改这几处口径时,先引这里;新的同类判断攒成一题一题、带真实对局例子去问。

## 伤害看需求,不看被迫的反应(2026-09-25)

提议「被踢后换了学派就算无害踢」被用户否:「被锁了肯定要做别的事,因果倒置了」。补充:「要看双方的压力,因为打断可以用来进攻也可以防守」。

- 失去资源后玩家的行为是由失去造成的,拿它当无害证据是循环论证。
- 量伤害看**窗口要求了什么、之后发生了什么**:队友血量 / 入伤 / 爆发 / 死亡、踢人者打断技冷却期间发生了什么——不看玩家接下来做了什么。
- 后续裁定:进攻 CD 跨度算压力(不只 HP ≤40% / 死亡);双方都平静时的踢不重要——除非我方爆发就绪;锁定造成的输出损失暂不做。

## 3v3 只复盘到第一次友方死亡(2026-09-30)

第一个队友死后比赛实际已结束,之后没施法、没交保命、打字都不算问题。找「空档 / 没交」只看开局到第一次友方死亡;死后段落最多作背景,不当问题、不拿去问用户。产品侧 3v3 首死封口用 `playableEndMs`。

## 身份准确性:模糊可以,指鹿为马不行(2026-09-22)

原话:「模糊可以接受,要看语境,但是指鹿为马不行」。

- 说「对面治疗」不点名专精没问题;**明确写错专精 / 职业**是硬伤(模型曾把对面神牧写成「奶骑」,把「圣骑的锤 + 治疗」拼起来)。
- 确定性兜底:`auditFindings` 的 `rosterClassViolations`,用**专精级**昵称表(职业级不够——Paladin 可能在阵容里)丢弃点名阵容外专精的 finding。
- 不要为了防模糊逼模型每处写全专精,也不要把「没写专精」当违规。模型侧错误用确定性 lint 兜底,别去调 prompt 措辞碰运气。
- 举例给用户前先核对谁是 owner、技能属于哪个职业 / 专精(曾举错过两次:技能其实是队友放的;某专精的打断技只是另两个专精的天赋)。打断技归属一律先查 `interruptKitGenerated` / `interruptForUnit`。

## 击杀与饰品

- **击杀三档机会模型(2026-08-18,勿再翻)**:prime(无徽章 + 可落满时长晕)> gated(无徽章但手里有 20–99% 大墙)> locked(有徽章)。免疫(冰箱 / 圣盾)不参与判档,逼出 = 赚;集火按全队算;「没有控制流的伤害基本没意义,只有高爆发例外」;模型只建在晕上。
- 饰品起手指控已退役(用户:「起手打有饰品的人……太扯了」)。`[KILL ATTEMPTS]` 只在有更软目标时点名。教训:事实块里的「档位」只在相对备选时有意义——渲染任何 tier / 标签前先问「此刻所有人是否都一样」。
- 「饰品绝对是用来解控制」:我方击杀尝试里对方交的饰品就算被逼出,不按血量门。

## 2026-09-26 的一批

- 烙印之火不算救人牌,也不算回应;戒律渐隐、神骑圣佑进救人名单。
- cd-hoarded 的「已回应」认 owner 自己的控制(peel)和任何队友的团队救。
- missed-sync-window:持有者锁内被控大半、只空闲 1 s 不算能按;目标身上有墙照样指控。
- Grounding / 反射 / 庇护的结果写成事实行;反射的控制技能一律写,没打出什么伤害的法术反射不写。
- 自己 / 宠物的打断技进 `[RES]`,不受 30 s 冷却下限挡。
- 对方开爆发后才交的墙不算 burst-into-mitigation 指控(反应式),只在墙早于爆发时指控。

## 其他口径

- 驱散旧四族话题每回合合计 ≤2(BACKLOG #22,用户裁**长期保留**)。
- 该不该救 = 伤情 × 已有保护一起看。
- 召唤物:大多数并进主人的伤害 / 控制,**不要通用名册**,只记功能性 / 大影响的;**不写「预期」时长**(日志没有消失事件,只写站了多久、何时被杀)。宠物方面用户纠正过:「DK 宝宝无所谓,猎人术士按理很重要」(术士宠物被杀后常整回合不回来)。
- 法力 / 次级资源方向关闭(2026-09-20):法力从指导上意义不大,次级资源属循环手法。
- 2v2 菜单只留 cd-hoarded + missed-cleanse(`BRACKET_TYPE_ALLOWLIST`)。
- **用户领域直觉与我的数字冲突时,先怀疑我量的是不是他说的那件事。**
