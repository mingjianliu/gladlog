# 价值门前置于工程门

CLAUDE.md 的 Value-Gate Rule 是规则本体;这里是由来和细则。

## 由来(2026-08-16)

两个 mana 候选走完「实现 → 标定 → A/B」全流程,数字全部复算无误;用户看到**一条输出例子**就判废话(「你这段蓝用多了」脱离敌方爆发的被迫性 = 无意义)。半天的标定与批量模型调用烧在一个十秒就能否掉的东西上。同日用户三次表达:深挖的价值在**归因推理链**,蒸馏成浅检测器丢掉了全部智能。

**Why**:评审体系只守数字正确性(复算 / 红线 / 谓词单源),没有任何关卡问「这东西值不值得存在」;工程质量越高,浪费在错形状上的成本越大。

## 做法

1. 任何新信号 / 候选,实现后第一步 = 产出**真实对局的完整输出例子**给用户看。没点头不进标定、不跑 A/B、不烧批量模型调用。
2. **归因类项目从输出倒推**:先拿真实对局手写目标结论句(「如果它是精良的,它该说什么」),用户批准后再造最小引擎;不先建管道。
3. 在归因引擎做出来之前,mana 类信号不往 prompt / UI 里加(2026-09-24 用户收窄为只限 mana)。
4. 先跑价值探针再向用户讲故事,且先 grep 产品是否已有同类逻辑。

## 价值门的真实例子反复抓到单测抓不到的问题

- prompt 行有**多个发射点**(台账 / 提升 / 普通施法),只接一条会「单测全过、生产一行不出」——之后每条都用测试钉全部路径。
- 朴素判别器会恒真(「覆盖那一刻的任意 buff」把耐力祝福排第一),必须对比同一情境的两种结局。
- 聚合器旧守卫吞掉全部分组(单测全绿、demo 出 0 个 cell 才现形);opener 用客户端语言原始名(同一 opener 分裂中英两条 + CJK 漏进 prompt)。
- **新聚合 / 新渲染必须跑一次真实语料 demo 再算完。**

## 「教练能教到东西」是取舍标准

用户清扫 issue 时(2026-09-05)的标准:能一眼从已有事实看出的东西不值得做成指控(「死亡时免疫可用」早在 prompt 的 `DEATHS WITH MISSED OPTIONS` 段);重复事实的第二套实现不留。
