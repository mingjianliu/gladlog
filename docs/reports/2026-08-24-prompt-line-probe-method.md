# Prompt 逐行效果探针:方法与八个坑(2026-08-23/24)

> 状态:**方法定稿,数据在采**。本文记方法与教训;三后端(claude/haiku、claude/sonnet、agy)
> 的对照数据跑完后另出结果报告。

## 要回答的问题

用户 2026-08-23:「我们现在发给 LLM 的每一行,LLM 都是怎么用的?有没有办法调整,能更好地
启发 LLM?」并明确要求:不做单局推演,**至少 100 盘**;固化成可复跑的工具;每个功能都用
类似推演验证;最终整合成一份报告。

一局 prompt 实测 361 行 / 30.6k 字符(154 局均值),行类型 40+ 种,前 14 类占 87% 字符
(普查口径:`packages/eval/src/explore/promptLineTypes.ts` 的 `classifyPromptLine`)。

## 为什么不用判官打分

`accuracy` 成对噪声底 SD≈1.3(|Δ|<0.4 测不出)、`sufficiency` 对植入缺陷检出率 20%
(docs/archive/HANDOFF-2026-07-20-judge-variance.md)。两维都不具备 A/B 裁决力。本方法一律用
**确定性的行为改变**做判据。

## 三种探法(单局验证均有效,已批量化)

| 探法 | 工具 | 回答的问题 | 判据 |
|---|---|---|---|
| 多轮追问 | 手工(scratchpad/interrogation) | 模型自述怎么用、归因、推理链 | 直接读;与消融交叉验证 |
| 消融 ablate | `scripts/promptAblationProbe.ts` | 这类行**有没有**被用 | 删掉整类后,结构化结论集合与基线的 Jaccard,配基线自比噪声底 + z 检验 |
| 植入 plant | `scripts/promptPlantProbe.ts` | 行里的**判断词**权重多大 | 反转结论词后,该时刻结论的极性翻不翻、模型是否察觉与 [STATE] 矛盾 |

### 单局验证的三个核心发现(存在性证明,发生率待批量)

1. **一行话能翻转裁决**:同一局只把一行 `[DMG SPIKE]` 的「48% -> 9% HP」改成「healed
   through」,模型对同一次防御的评价从「你打得完美」翻转成「纯粹的恐慌交、浪费了」,
   且**未察觉与同一份 prompt 里 [STATE] 的矛盾**,还编出了 prompt 里没有的因果。
2. **模型自述**:3 条结论只有 1 条用到 `[DMG SPIKE]`;唯一增量是速率(`-4%/s`);
   `— healed through` 类行与 `Top sources` 被点名「没有增量价值」;想要而没有的:伤害
   可否被减、spike 前的预警、spike 期间敌方是否用 CC 掩护。
3. **推理链末步全是假设**:三条推理链的最后一步全是模型自标的【我假设的】(反事实),
   包括一处自己做 CD 算术且用错数值(Hex 按 15s 算,现版本 30s)。

## 八个坑(全部是测量工具的缺陷,不是被测对象的)

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | 没有对照组 | 27 类 Jaccard 挤在 0.275–0.450,信号噪声不可分 | 每局跑多次基线,两两互比得噪声底;只有低于 μ−σ 才谈得上效应 |
| 2 | 采样噪声 | 生产温度下删掉 16.5% 字符的 [STATE] 测出的 Jaccard **比噪声底还高** | 探针显式 temperature 0(生产口径可用 `--temperature default` 还原) |
| 3 | 指标混极性 + 截断 | 同主题 good/bad 会翻;maxTokens 3072 切断 10% 的 JSON | 结论键只用 topic;maxTokens 6144;parseFindings 括号配平抗截断 |
| 4 | 后端故障不熔断 | DeepSeek 余额尽后**空转 2,766 次/1 小时**,进度条一路正常 | `Breaker`:连续 N 次失败中止 |
| 5 | 中止丢数据 | agy 熔断时丢掉已完成的 560 次 | 每 25 次增量落盘 + 同 `--out` 断点续跑(熔断管「不空转」,不管「不丢数据」,两件事) |
| 6 | 错误信息为空 | claude 限流时只有「退出码 1: 」 | stderr 与 stdout 都截取进错误 |
| 7 | 瞬时限流当终止 | 13 路并发触发限流,熔断误杀两批 | 指数退避重试 3 次,重试尽才计入熔断 |
| 8 | **CLI 加载仓库上下文** | cwd=仓库时 75s/次且答非所问(回答本仓库的 eval-baseline 工作流);cwd=空目录 25s/次、正常分析 | spawn 于 `mkdtemp` 中性目录。**评测脚本所在的仓库本身是污染源** —— 它恰好装满关于被测产品的说明 |

坑 8 的代价:修复前的三批数据(haiku 628 / sonnet 117 / agy 560 样本)**全部作废**。
haiku 曾测得的 0.556 噪声底,修复后回到 0.755 ± 0.035(方差小 5.5 倍)—— 「模型不稳定」
大半是测量环境造成的。

## 通用纪律(从这次固化)

- 批量任务的默认假设是**会被打断**,不是一次跑完(一天被打断三次:余额/额度/限流);
- 噪声底先行:任何比较型指标,先跑基线自比,再谈效应;
- 语料清单钉快照:归档目录一天内从 10,676 涨到 18,134,不钉快照前后测的不是同一批;
- 静态扫描出的比例本身要验证:本轮两次「数错」(86→68、KILL ATTEMPTS 0%→100%)都是
  判据比问题窄。
