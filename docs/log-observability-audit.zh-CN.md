# 战斗日志可观测性审计

[English](log-observability-audit.md) | **简体中文**

## 目的与范围

跟踪：[GH #100](https://github.com/mingjianliu/gladlog/issues/100)。

用户方向（2026-09-19）：先探索收集到的日志里有哪些产品没用上的信息，再考虑新增启发式教练建议。区分观测事实、推断状态、有意不呈现和真正不可观测的信息。本审计不授权新增教练指控。

首轮探针和与 Claude Opus 5 的两轮讨论已完成。没有修改产品谓词。600 文件分层探索和全归档普查**尚未运行**。

## 可复现探针

```sh
npx tsx packages/eval/scripts/logObservabilityPilot.ts \
  "$GLADLOG_EVAL_HOME/corpus/manifest-archive-2026-09-14-newseason.txt" \
  "$GLADLOG_EVAL_HOME/reports/log-observability-2026-09-19/replay.json" 24
```

将 `GLADLOG_EVAL_HOME` 设为私有评估目录，先创建输出目录。脚本拒绝覆盖已有结果。JSON 包含私有文件路径和各文件解压内容的哈希，不提交仓库。脚本逐文件解压，不把全归档装入内存。

- 清单：63,303 个文件；SHA-256 `72e05f5de27d095a03f6cb5cde802475442d825c7a9925568a5095b2bd142a1e`。
- 保持清单顺序，取索引 `floor((i + 0.5) * N / 24)`，`i = 0..23`。
- 使用已有 `splitLine`、`parseLine` 读取 671,928 个非空行。全部返回 ParsedLine，**不代表**字段语义正确或完整解码。
- 有 39 条 ARENA_MATCH_START，不是 39 个确认独立完整的回合。本探针没有分割、去重回合或按阵容分层。
- 探索样本用于证明存在与发现实现缺口，不估计赛季发生率。文件、大厅、回合、角色与重复视角是不同分母。

## 已有工作与排除的假发现

- 已归档 BACKLOG #36 记录了资源、IMMUNE、DAMAGE_SPLIT、EMPOWER、治疗吸收的解析修复。当前 matchTimeline.ts 已消费 IMMUNE 和 EMPOWER，不是新缺失事件类型。
- 治疗吸收不进 prompt 是有意裁决：此前 1,200 回合 / 1,322 次死亡研究中，死亡前 10 秒有吸收的 56 次，超过受害者最大血量 20% 的仅 6 次，且不少来自自身代价。保留数据，不凭事件数重启教练功能。治疗吸收和百分比减疗是不同机制。
- slim.ts 将 params 截为 13 项并清空字段。convertParams 保留数组不证明旧文档还保留原始内容。新解析与旧文档恢复需要分别验证。
- 实际伤害/治疗可能已包含装备、天赋效果。还原机制或可用性需要这些效果；汇总实际结果不能再次乘加成。

## Claude 讨论

通过本机 Claude CLI 做了两轮只读讨论，实际后端 claude-opus-5。Codex 跑探针并核对源码，Claude 没有扫描语料。

Claude 提出审计未解高级字段、COMBATANT_INFO 标量属性、失败施法和 NPC 状态。这些仍是调查假设，尤其护盾余量、护甲、输出属性和资源消耗：原始偏移与语义**尚未验证**。

收到探针数据与反例后，Claude 接受了以下修正：旧文档未必可恢复、IMMUNE 已有消费者、治疗吸收有意不呈现、actor 不等于 caster，以及不能说动态冷却永远不可还原。同施法者×法术配对也不能独立识别减疗强度，仍受抑制、触发、天赋、暴击与目标受疗修正混杂。

Codex 继续保留的限制：失败施法是否只覆盖记录者仍需验证；高级 actor 样本可能来自受伤/治疗，不只来自该角色施法。一次失败只约束瞬间，不证明整个区间不可施法。角度插值需单独验证语义。

## 逐项探索队列与验收

### 方向 1：朝向的首轮证据

对首轮输出运行 `npx tsx packages/eval/scripts/facingObservabilityScan.ts <pilot.json> <new-output.json>`。脚本核对输入文件哈希，在观察到的竞技场开始/结束及文件边界断开间隔配对。它只是诊断，不是产品朝向谓词。

同一批 24 文件有 223,516 条有限数值的 Player-actor 样本：62,772 条 actor=source，160,729 条 actor=destination，15 条两者皆非（全部 SPELL_CAST_SUCCESS）。自施事件计入 source。因此，将朝向归给施法者而不是 advanced.actorGuid，在大量记录上会出错。

朝向范围为 0–6.2832，与舍入后的弧度表示相容，但**不能证明**单位、零度轴、旋转方向或世界坐标到地图的转换。一条略高于数学上的 2π，未核对精度前不能判坏样本。

共有 194,566 个 actor/时间戳组，21,503 组含多条记录；15 组朝向不一致，16 组位置不一致。这不证明数据损坏，还需核对事件顺序和毫秒内变化。静止配对诊断排除这些不一致组。57,528 对相邻样本的记录 x/y 完全相同且间隔不超过 1.5 秒，其中 10,650 对朝向改变，说明不能把该字段仅当移动方向；坐标舍入也意味着不能证明角色实际完全没移动。

194,350 对相邻样本的间隔（按样本对计，不按时长/玩家加权）：p50 0.077 秒、p90 0.375 秒、p99 1.204 秒；1,078 对超过 1.5 秒，228 对超过 3 秒，最长 29.005 秒。这不代表 99% 战斗时间可观测；空闲/潜行、缺失回合边界、死亡和角色活动密度需要独立分母。

**当前结论**：保存角色实际观测朝向及时间戳/来源，是有证据支持的数据层方向。“面向目标 X”、连续朝向、镜头方向和战术判断仍未验证/获批。未完检查包括独立坐标轴/单位校准、15 条第三角色施法、同毫秒差异，以及按回合/玩家/时长计算的空档覆盖。没有修改产品。

一次推进一个方向，先给出具体、有证据的结果，再扩大范围：

1. **朝向**：验证 actor 归属、角度单位/范围、采样缺口、同角色同时间一致性。确定可保留什么，不推断镜头或战术意图。
2. **未解状态字段**：用独立事件证据检验候选语义，不能因偏移看着合理就认定护盾/属性字段。
3. **资源**：解码并对账恢复、流失、消耗与快照；验证施法前后时序及覆盖。
4. **NPC**：建立观测 npcId 清单，区分观察到出生/活动/死亡与消失未知；保留 NPC 与主人的分别归属。
5. **装备与动态天赋**：借官方证据连接配置和实际效果，可见的状态变化才能回放，否则保留不确定；审计绕过已有修正的消费者。

交付物是逐字段链路：**raw → L1 → L3 → compat → analysis → prompt**，标记已消费、未解码、途中丢失、已解码未消费、有意不呈现、语义未验证或不可观测。known=true 不等于完整解码。

定义验证后，先用上限 600 文件分层探索（版本/日期、赛制、地图、专精、记录者和高级日志覆盖）。去重大厅和回合的重复记录，稀有机制定向样本单独报告。之后才进行程序化、顺序全清单普查，分别报告事件/单位/回合分母及缺失/错误数。不逐局调用 LLM。更多观察不能补出未记录的意图、镜头状态或输入。

产品事实变更需确定性前后验证；新增教练结论仍需完整真实比赛样例与用户审阅。
