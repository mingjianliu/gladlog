  "$GLADLOG_EVAL_HOME/corpus/manifest-archive-2026-09-14-newseason.txt" \
  "$GLADLOG_EVAL_HOME/reports/log-observability-2026-09-19/replay.json" 24

将 `GLADLOG_EVAL_HOME` 设为私有评估目录，先创建输出目录。脚本拒绝覆盖已有结果。JSON 包含私有文件路径和各文件解压内容的哈希，不提交仓库。脚本逐文件解压，不把全归档装入内存。

- 清单：63,303 个文件；SHA-256 `72e05f5de27d095a03f6cb5cde802475442d825c7a9925568a5095b2bd142a1e`。
- 保持清单顺序，取索引 `floor((i + 0.5) * N / 24)`，`i = 0..23`。
- 使用已有 `splitLine`、`parseLine` 读取 671,928 个非空行。全部返回 ParsedLine，**不代表**字段语义正确或完整解码。
- 有 39 条 ARENA_MATCH_START，不是 39 个确认独立完整的回合。本探针没有分割、去重回合或按阵容分层。
- 探索样本用于证明存在与发现实现缺口，不估计赛季发生率。文件、大厅、回合、角色与重复视角是不同分母。

## 已有工作与排除的假发现

- 已归档 BACKLOG #36 记录了资源、IMMUNE、DAMAGE_SPLIT、EMPOWER、治疗吸收的解析修复。当前 matchTimeline.ts 已消费 IMMUNE 和 EMPOWER，不是新缺失事件类型。
- 治疗吸收不进 prompt 是有意裁决：此前 1,200 回合 / 1,322 次死亡研究中，死亡前 10 秒有吸收的 56 次，超过受害者最大血量 20% 的仅 6 次，且不少来自自身代价。保留数据，不凭事件数重启教练功能。治疗吸收和百分比减疗是不同机制。
- slim.ts 将 params 截为 13 项并清空字段。convertParams 保留数组不证明旧文档还保留原始内容。新解析与旧文档恢复需要分别验证。
- 实际伤害/治疗可能已包含装备、天赋效果。还原机制或可用性需要这些效果；汇总实际结果不能再次乘加成。

## Claude 讨论

通过本机 Claude CLI 做了两轮只读讨论，实际后端 claude-opus-5。Codex 跑探针并核对源码，Claude 没有扫描语料。

Claude 提出审计未解高级字段、COMBATANT_INFO 标量属性、失败施法和 NPC 状态。这些仍是调查假设，尤其护盾余量、护甲、输出属性和资源消耗：原始偏移与语义**尚未验证**。

收到探针数据与反例后，Claude 接受了以下修正：旧文档未必可恢复、IMMUNE 已有消费者、治疗吸收有意不呈现、actor 不等于 caster，以及不能说动态冷却永远不可还原。同施法者×法术配对也不能独立识别减疗强度，仍受抑制、触发、天赋、暴击与目标受疗修正混杂。

Codex 继续保留的限制：失败施法是否只覆盖记录者仍需验证；高级 actor 样本可能来自受伤/治疗，不只来自该角色施法。一次失败只约束瞬间，不证明整个区间不可施法。角度插值需单独验证语义。

## 逐项探索队列与验收

### 方向 1：朝向的首轮证据

对首轮输出运行 `npx tsx packages/eval/scripts/facingObservabilityScan.ts <pilot.json> <new-output.json>`。脚本核对输入文件哈希，在观察到的竞技场开始/结束及文件边界断开间隔配对。它只是诊断，不是产品朝向谓词。

同一批 24 文件有 223,516 条有限数值的 Player-actor 样本：62,772 条 actor=source，160,729 条 actor=destination，15 条两者皆非（全部 SPELL_CAST_SUCCESS）。自施事件计入 source。因此，将朝向归给施法者而不是 advanced.actorGuid，在大量记录上会出错。

朝向范围为 0–6.2832，与舍入后的弧度表示相容，但**不能证明**单位、零度轴、旋转方向或世界坐标到地图的转换。一条略高于数学上的 2π，未核对精度前不能判坏样本。

共有 194,566 个 actor/时间戳组，21,503 组含多条记录；15 组朝向不一致，16 组位置不一致。这不证明数据损坏，还需核对事件顺序和毫秒内变化。静止配对诊断排除这些不一致组。57,528 对相邻样本的记录 x/y 完全相同且间隔不超过 1.5 秒，其中 10,650 对朝向改变，说明不能把该字段仅当移动方向；坐标舍入也意味着不能证明角色实际完全没移动。

194,350 对相邻样本的间隔（按样本对计，不按时长/玩家加权）：p50 0.077 秒、p90 0.375 秒、p99 1.204 秒；1,078 对超过 1.5 秒，228 对超过 3 秒，最长 29.005 秒。这不代表 99% 战斗时间可观测；空闲/潜行、缺失回合边界、死亡和角色活动密度需要独立分母。

**当前结论**：保存角色实际观测朝向及时间戳/来源，是有证据支持的数据层方向。“面向目标 X”、连续朝向、镜头方向和战术判断仍未验证/获批。首轮之后未完的检查——独立坐标轴/单位校准、15 条第三角色施法、同毫秒差异，以及按回合/玩家/时长计算的空档覆盖——已由下面的校准一节收口。没有修改产品。

### 方向 1：校准

对同一份首轮输出运行 `npx tsx packages/eval/scripts/facingCalibrationScan.ts <pilot.json> <new-output.json>`。同一批 24 个核对过哈希的文件，39 个片段：24 个以 `ARENA_MATCH_END` 收尾，15 个以下一条 `ARENA_MATCH_START` 收尾（单排一个大厅只记一条 END），后者取首个名单内角色阵亡为结束。仍是探索样本：用来确立约定和机制，不估计赛季发生率。

**actor 归属。** 15 条 actor 不等于两端的记录是同一种机制。全部是无来源的 `SPELL_CAST_SUCCESS` 145629（反魔法领域的区域光环落到某个玩家身上）。15/15 的 advanced actor 是名单内 Player 且与 destination 同队；其记录位置在 15/15 中与该 actor **自己**上一条样本相距不超过 1.5 码（最大 1.31 码），与 destination 上一条样本相距 1.5 码以内的为 0/15。11/15 中该 actor 在此前 1.2 秒内施放了 51052（反魔法领域技能本体），其余 4 条是之后再次走进已存在的领域。因此高级块是领域主人自己的状态——不是 destination 的，不是地面坐标，也不是解析 bug。结论：朝向样本只按 `advanced.actorGuid` 归属，绝不按事件的 source 或 destination。

**角度约定。** 八种坐标轴/符号约定在两个独立来源上竞争：同毫秒的 `SWING_DAMAGE`（攻击者样本）与 `SWING_DAMAGE_LANDED`（目标样本）配对，间距不足 1 码的跳过；以及 0.5 秒内位移至少 1.5 码、速度 5–12 码/秒且朝向变化不超过 0.1 弧度的相邻样本。

| 约定（记录位移的角度）      | 近战方位落在 90° / 30° 内（n = 2,038） | 移动方向落在 90° / 30° 内（n = 7,938） |
| --------------------------- | -------------------------------------: | -------------------------------------: |
| `atan2(dy, dx)`             |                       97.25 % / 67.6 % |                        78.9 % / 38.4 % |
| `atan2(-dy, -dx)`（其反向） |                         2.75 % / 0.5 % |                         21.2 % / 0.9 % |
| 其余六种                    |                    48.0–52.0 % / ≤18 % |                    48.8–51.3 % / ≤20 % |

因此该字段是弧度，θ 指向**记录坐标** x/y 中的 `(cos θ, sin θ)`：0 为 +x，π/2 为 +y。移动方向只是部分吻合，这是构造使然——玩家会平移和后退。本轮未确立：记录 x/y 如何映射到渲染的地图图像（回放的坐标变换是另一件事实），以及 2.75 % 目标在攻击者身后的挥击是什么（未查；两条样本并非真正同时是候选解释之一）。

**同毫秒差异。** 20 个有差异的组（4 个仅朝向、5 个仅位置、11 个两者皆有），量级约为每一万个 actor/时间戳组 1 个。其中 14 组在 100 毫秒内有下一条样本：靠后的日志行更接近下一条样本的 7 组，靠前的 7 组。所以一毫秒之内的行序不携带可用的时间先后：它们是无序的同时间戳观测。在这个比例下，任何确定性的取舍都无害，只要不把它描述为“最新”。

**按时长加权的逐玩家-回合覆盖**（区间 = 该玩家首条样本到其自身阵亡或片段结束）：

|                                            |             END 收尾 |    下一条 START 收尾 |
| ------------------------------------------ | -------------------: | -------------------: |
| 玩家-回合数 / 玩家-秒                      |         126 / 20,540 |          90 / 10,181 |
| 落在 ≤ 1.5 秒间隔内的时长                  |               91.3 % |               91.4 % |
| 落在 ≤ 3 秒间隔内的时长                    |               95.8 % |               97.6 % |
| 逐玩家-回合 ≤ 1.5 秒占比：p50 / p10 / 最小 | 92.2 / 77.6 / 54.6 % | 92.3 / 72.1 / 54.5 % |
| 逐玩家-回合最长间隔：p50 / p90 / 最大      |  4.2 / 9.2 / 23.0 秒 |  2.5 / 6.9 / 11.3 秒 |

没有名单内玩家的样本少于两条。间隔的含义是“没有高级记录以该角色为 actor”，不是“玩家什么都没做”；潜行、视线遮挡和空闲时间没有单独剥离。

**方向 1 结果。** 可以作为观测事实保存的：按 `advanced.actorGuid`，元组（时间戳、x、y、朝向——弧度，指向记录坐标轴的 `(cos θ, sin θ)`），且只在有高级记录以该角色为 actor 的时刻存在。必须保持未知的：样本之间的朝向（中位玩家-回合里有一个 2.5–4.2 秒的空洞，约 8.7 % 的玩家时长落在超过 1.5 秒的间隔里）、镜头方向、意图目标，以及关于间隔本身的任何事。“某个样本时刻单位 X 是否在该角色正面弧内”在两者该时刻都有位置时已是可计算的几何。L3 是否保存朝向、是否有消费者使用它，是两项独立的用户决定；本文都不做。没有修改产品。

### 方向 1：保存与消费者的决定（codex astra 辩论，2026-09-19）

与 codex `gpt-6-astra` 两轮（会话 `codex:01a0bcf1-3060-7a10-aa98-7476fca39b98`），它以 `STANCE: CONCEDE` 收在下面的裁决上。开场立场：L3 不保存朝向，不做教练消费者，至多做一个只展示的回放刻度。

向 codex 让步的：价值门规则管的是信号和候选，不管已解码观测的保留（治疗吸收是先例）；体积理由不成立——每个抽样文件约 12,600 条高级记录 × 16 字节 ≈ 0.2 MB，约为一场存档的 0.3 %；`rawStreams` 只暴露法力样本和失败施法，朝向原型需要新的流提取；“超过 1.5 秒的间隔不插值”错误地默许了低于该值的插值；91.3 % 是间隔覆盖、78.9 % 验证的是约定——两者都不是朝向精度或后退分类器的数字；未解释的 2.75 % 目标在身后却挥击成功，本身就是对任何硬性正面弧门的警告。

codex 让步的：它的核心论据是不保存等于“继续不可逆地删除”。在真实库上核对：**1,095 / 1,095 场存档都保留了非空的 `raw.txt`**（19 GB）——`matchStore.store()` 每次导入都写，`readRawText()` 已在读。新旧对局的朝向都可恢复，这也否定了开场立场里“瘦身后的对局无法回填”的说法。保留意见：`reparse()` / `rebuildIndex` 只从 `match.json` 重新派生 meta，没有任何路径把 `raw.txt` 重新解析成新的 `match.json`，全库回填需要新建这条路径。

审过的教练消费者**一个都没批**：漏踢 / 需要正面的晕、近战“绕背”、后退走位、盗贼/野德的站位要求、治疗背对。每一个都需要逐技能核实的限制，外加事件驱动采样给不出的可行性论证——某一条样本背对不能说明玩家当时转不过来。2026-09-05 的锥形打空否决维持。可信的非教练用途：通过近战事件做解析/回放校验（校准已经这么做了），以及佐证视频↔日志配对。

**裁决（双方一致）：** L3 保存推迟到有消费者获批；届时再加可选字段、到解析器 oracle 登记，并一次性建好 `raw.txt` 重新解析路径。决定性的考虑是保留的原始日志可恢复。**用户裁决，2026-09-20：不做——“收益不大”。方向 1 收口：不保存、没有任何消费者使用朝向，上面校准出的约定留档，供将来重开的人使用。** 当时提给用户的是：是否做提议的第一个消费者——回放里选中玩家的朝向刻度，显示观测样本及其年龄，绝不显示插值方向。动工前的前置：验证从记录方向到回放的完整变换，包括镜像和旋转；点的位置画对了不能证明方向画对了。

### 原始日志保留约束

在审计列出的、持久化结构数据里没有的每个字段都有经过验证的无损替代之前，不得发布任何删除、截断或有损替换存档 `raw.txt` 的改动。已验证的字段（朝向）物化保存；未解码的字段连同事件身份、时间戳、已知的 actor 关联和来源原样保留——绝不物化成猜测的含义。先验证替代，再删除源。该约束也在以下两处被引用： `packages/desktop/src/main/matchStore.ts` 写 `raw.txt` 处和 `packages/parser/src/slim.ts` 的文件头。
