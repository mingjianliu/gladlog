# Predicate Index

**English** · [Chinese](predicate-index.zh-CN.md)

The place to look up "does this fact already have a predicate?" — before you write a constant, a threshold, a tolerance, a sampler, or a formatter.

## Why this page exists

`CLAUDE.md`'s first hard rule is the **shared-predicate rule**: analysis code (`packages/analysis`) and the verification gates (`packages/eval`) must decide **the same fact** with **the same predicate** — same constant, same sampling function, same tolerance — anchored on the _rendered_ value, because the gates re-parse the rendered prompt text. The rule also states the remedy: export the predicate in one place and import it on both sides; when that is impossible, write a unit test that asserts equality — do not rely on a comment.

The historical cost of breaking it: in the 2026-07 full-corpus audit, **five independent bugs were all this one class** — inconsistent HP sample radius, bounded vs unbounded backtracking, interpolated vs raw vs off-instant sampling for line of sight, and fractional seconds vs the rendered-second scan grid.

The rule was never the missing piece. On 2026-08-01 the same person, having read the rule, re-implemented two predicates by hand inside a single day's work: the "match already known" test was copied into the orchestration shell, and `dateKey` formatting was written out a second time in another file. **What was missing is an index** — somewhere to see, before writing new code, that the fact already has an owner.

## How to use it

**Before writing new code.** Search the table for the _fact_, in words — not for a symbol name you half-remember. If the fact is listed, import the predicate. Do not re-derive it, do not copy the literal, do not inline "just this once" a regex that already exists.

**When you add an "analysis asserts X, the gate verifies X" pair:**

1. Export the predicate from one module and import it on both sides.
2. Add a row to the index below — in **both** language versions.
3. Add the same row to `packages/eval/test/predicateIndex.test.ts`. That test parses this page, so the page and the test cannot rot apart.
4. If sharing the export is genuinely impossible — the other side is a markdown spec, a rendered string, or a different language — add an equality assertion to that same test. That is CLAUDE.md's explicit fallback, and a comment is not a substitute for it. `FACT_AUDIT_MIN` / `FACT_AUDIT_MAX` below is the worked example.

**When you rename or delete a predicate.** The test imports every symbol listed here, by file path. A rename breaks CI; update this page in both languages instead of deleting the row.

## Reading the table

- **Fact** — what gets decided, in words. This is the column to search.
- **Authoritative predicate** — `file` → `export`. Exactly one per fact.
- **Consumed by** — notable call sites, not an exhaustive list. "gate" means `packages/eval`.
- **Notes** — the semantics that are easy to get wrong.

Paths are relative to the repository root. Everything under `packages/analysis/src` can be imported by file path; most of it is also re-exported from the package root (`@gladlog/analysis`), but `factFormat.ts`, `spellCategories.ts`'s `isCastBlockingAuraType` and a few others are reachable only by file path.

**Scope.** The rule the index serves is "one fact, one predicate", and that is not confined to the analysis/gate pair. A fact decided by two consumers _inside_ the desktop renderer — a number the leaderboard prints and a bar the chart next to it draws — fails the same way and belongs here too (the `desktop-dev` skill calls this the UI edition of the rule). The `Report UI` section below is that case; everything else is analysis-authoritative.

Not duplicates — recorded so nobody "unifies" them by mistake:

- **"Closest distance in a window" is sampled differently by producer and gate _on purpose_.** `positionAnalysis.ts` walks whole seconds with `INTERP_MAX_GAP_MS` (1500 ms); the gate's `minDistanceInWindow` walks whole seconds _plus_ every advanced-action timestamp _plus_ a sub-second grid, with `LOS_SWEEP_GAP_MS` (3000 ms). The gate's instants are a strict **superset** of the producer's and its gap is looser, and `getUnitPositionAtTime`'s gap only accepts or rejects a sample without changing its value — so `gateMin ≤ producerMin` always holds, and the gate's one-sided test ("claimed closer than physically observed") is the correct expression of that direction, not a workaround. Making the producer adopt the gate's gap would be a regression: `INTERP_MAX_GAP_MS` is the T3 grounding guard that killed fabricated mid-gap interpolation (a false 0.4 yd trained claim). The relationship is pinned end to end in `predicateIndex.test.ts` — the real producer's rendered claim must pass the real gate, with a wrong-window negative control. Only the sampling **instants** are shared, via `positionSampleInstants`.
- **The managed idle-split cadence and the orphan grace window are not the same fact**, though they were both 10 minutes and `ORPHAN_GRACE_MS`'s comment used to say it "mirrors" `IDLE_SPLIT_MS`. `recorder.ts` → `IDLE_SPLIT_MS` bounds how much pre-match lobby footage sits at the head of a match's file (60s since the 2026-09-05 ruling); `recordingsStore.ts` → `ORPHAN_GRACE_MS` (10 min) bounds how long an unclaimed chunk is protected from the orphan cap while its `associate()` message is still in flight. Shortening the cadence only means more orphans sit inside the grace window at once, which is what the window is for — deriving one from the other would silently couple retention safety to a recording-layout preference.
