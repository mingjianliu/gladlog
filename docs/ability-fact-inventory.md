## Tier Definitions

Ability fact assertions are divided into three tiers (see the background section of `docs/superpowers/specs/2026-08-14-ability-fact-grounding-design.md`):

1. **Officially backed**: Generated from wago.tools DB2 tables via `resolveBuild()` in `packages/analysis/scripts/datagen/*.ts`; outputs are covered by anti-corruption tests in `packages/analysis/test/datagenManifest.test.ts`.
2. **Manual whitelist**: Publicly verifiable game facts (which spec a spell belongs to, CD/duration order-of-magnitude, dispel type, etc.), manually curated into TS constant tables. Some entries have additional corpus cross-validation (hit counts / medians), but the **existence and structure** of the table itself is not machine-generated from DB2.
3. **Pure prior, zero-data backing**: Hand-written assertions with neither official field verification nor corpus cross-validation—the flagship case named in the design document is `USABLE_WHILE_CC_SPELL_IDS` (cooldowns.ts:127, only 6 hand-written ids). **This flagship case was migrated out of this tier on 2026-08-14 in this project (Task 3/5/6), see the corresponding row in the A1 table below—this definition is retained as-is for historical record only and is no longer the current sole/primary example.**
